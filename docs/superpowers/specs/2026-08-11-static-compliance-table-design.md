# Static Compliance Table Build Step — Design

**Date:** 2026-08-11
**Goal:** Make the iGaming Compliance Map's 211-regulation database visible to non-JS crawlers and AI systems by pre-rendering the full table into `igaming-compliance.html` at build time, and stop the published counts from ever drifting from the data again.

## Background

The regulation database lives only in `igaming-compliance.js` (`const REGULATIONS = [...]`, ~114KB). The shipped HTML table contains a header row only; `refreshTable()` fills `#igc-table-body` client-side. Non-JS crawlers (and most AI retrieval systems) see none of it. Published counts (210/203, 50/60+) had drifted from the real data (211 regulations, 50 jurisdictions) and were fixed by hand on 2026-08-10 — this build step makes them generated instead.

## Components

### 1. `generate-compliance-table.py` (new, repo root)

Follows the `generate-news-links.py` pattern exactly: marker-splice regeneration, `--hook` flag for PostToolUse filtering, fails loudly with a non-zero exit on any structural surprise. Root `.py` files are already excluded from FTP deploy, so nothing new ships to the server.

**Data extraction and row rendering:** the `REGULATIONS` array references JS constants (e.g. `EEA`) that regex cannot safely parse. The script shells out to `node` and evaluates the file prefix up to the end of the `REGULATIONS` definition (`new Function(prefix + '; return {REGULATIONS, COUNTRY_META};')`). The same Node snippet then renders the table rows using row-building code copied verbatim from `refreshTable()` (jurisdiction logic, `catLabel`, `escHtml`, template literal), so the generated markup cannot diverge from what the page's JS produces. It prints `{rows, regCount, jurCount}` as JSON to stdout; Python only splices and stamps. If `node` is missing or evaluation fails, the script errors out — it never writes partial output.

### 2. Static table rows in `igaming-compliance.html`

New markers inside `#igc-table-body`:

```html
<tbody id="igc-table-body">
  <!-- static-regs:start - generated by generate-compliance-table.py, do not edit by hand -->
  ... 211 <tr> rows ...
  <!-- static-regs:end -->
</tbody>
```

Row markup must be **byte-identical to what `refreshTable()` produces** for the default (unfiltered) view, including:

- Jurisdiction cell logic: `eu-wide` → `🇪🇺 EU / EEA`, `global` → `🌐 Global`, more than 3 countries → first 2 as `flag Name` + `+N more`, otherwise all countries joined with `, ` — flags and names from `COUNTRY_META`.
- Category badge: `<span class="igc-badge igc-badge-{category}">{label}</span>` using the same category-label mapping as the JS `catLabel()`.
- Official link markup with `target="_blank" rel="noopener noreferrer"` and the `open_in_new` icon span.
- Same HTML-escaping as the JS `escHtml()`.

No JS changes: on load `refreshTable()` overwrites the tbody with identical content (no flash, no layout shift). If JS fails, the full table is simply present. Size cost ~65KB uncompressed, <10KB over the wire with brotli.

**Row order** must match `getFilteredRegs()`'s default ordering so the pre-rendered and hydrated tables are identical.

### 3. Auto-counts

After rendering rows, the script computes from the data:

- regulation count = `REGULATIONS.length`
- jurisdiction count = unique values across all `countries` arrays

and regex-stamps them into the existing phrasings:

- `igaming-compliance.html`: meta description, `og:description`, `twitter:description`, Dataset schema description, intro paragraph ("covering N regulations, directives and licensing frameworks across M jurisdictions"), Key Points ("N regulations tracked across M jurisdictions"). The Key Points "as of Month Year" stamp is refreshed to the current month/year on every run where the generated block changed.
- `llms.txt`: the compliance-map line ("N iGaming regulations across M jurisdictions").

Each stamp is a targeted regex (`\d+` in a known phrase context); if a phrase is not found, the script fails loudly rather than silently skipping.

`index.js`'s tool-card description also mentions the counts but is **not** auto-edited (editing it would require a cache-bust bump in `index.html`). Instead the script compares and prints a prominent warning if it drifts, telling the user to update `index.js` and bump `?v=` manually.

### 4. Hook + workflow

Add a second command to the existing `PostToolUse` entry in `.claude/settings.json`:

```json
{ "type": "command", "command": "python generate-compliance-table.py --hook" }
```

With `--hook`, the script reads the tool-call JSON from stdin and exits 0 silently unless the edited file path ends with `igaming-compliance.js`. Every future data edit then regenerates the static table and counts automatically.

## Error handling

- Missing markers in the HTML → error, exit 1.
- Node unavailable / eval failure / zero regulations parsed → error, exit 1.
- Any expected count-phrase not found → error, exit 1.
- Idempotent: re-running with unchanged data produces no file changes (and does not touch the "as of" date).

## Verification

1. Run the script; confirm exactly 211 rows between the markers and counts stamped everywhere.
2. Diff a sample of generated rows against the browser-rendered rows (copy from DevTools) — must match.
3. Re-run immediately; confirm "already up to date" and zero diff (idempotency).
4. Open the page locally with JS disabled — full table visible; with JS enabled — filters, tabs and search still work, no visual flash.
5. After deploy: `curl https://johnb.io/igaming-compliance | grep -c '<tr'` returns 212 (211 + header).

## Out of scope

- Per-region static pages (possible follow-up, separate spec).
- Rendering the `notes` field into the table (the table matches the interactive view; notes stay in the country panel).
- Auto-updating `sitemap.xml` lastmod (manual, per existing checklist).
